# 业务口径

写给要改学生、班级、出勤作业、账户邀请、管理员或收费功能的人：每个业务概念现在按什么规则运作，以及为什么这样定。课堂本身的数据流见 `kb/docs/classroom-session-lifecycle.md`。

## 学生姓名

每个学生有英文名和中文名。英文名必填，是主显示名，头像首字母也取它；中文名可空，作为小字显示在班级学生卡片、分组成员、收款单行和成长档案头部。考勤页与课堂页只显示英文名。

- 数据库里英文名存在 `students.name`（历史列名沿用），中文名存在 `students.cn_name`。
- 改名接口区分「没传中文名」与「传了空值」：没传则不动，传空串或空白则清空。这是为了让只会发英文名的旧页面不会误清中文名。
- 家长注册申请里的中英文名是注册那一刻的快照，与学生档案上的名字是两回事。老师关联申请时，中文名只在学生档案为空时回填。
- 战报、上课记录、收款单都不存姓名快照，读取时现查。改名后刷新即全部生效。

## 学生状态

| 状态 | 含义 | 进课堂 | 计入班级人数 |
|---|---|---|---|
| active | 在读 | 是 | 是 |
| suspended | 停课 | 否 | 是 |
| archived | 归档 | 否 | 否 |

- 非在读学生不进课前配置、课堂和上课记录快照，也不算缺席。
- 停课或归档时立即清掉该生的默认分组座位；恢复后需要老师手动拖回组。
- 已绑定家长看历史战报不受状态影响。

## 班级归档

班级归档后从首页班级列表移入归档列表，禁止新建课程周期和收款项。收银台创建收款项只列出未归档班级；再次打开弹窗时，原选择若已归档或删除，自动改选首个可用班级，没有可用班级时禁止提交。归档班的排班 tab 显示禁用的新建按钮及取消归档提示，服务端也会拒绝这两种创建请求。

历史排班和收款记录仍可查看、编辑、重算和收款。取消归档后可重新创建。归档班照常可以进详情、开课，在课堂列表筛选、小程序老师端、管理页里也照常出现。

它与学生的「归档」状态无关。归档在「编辑班级信息」弹窗里勾选，已归档的班收在 `/classes?is_archived=true`。

## 账户与邀请

学生是教学实体，微信账户是登录身份，两者分开：

- 老师与微信账户：在小程序绑定页用登录名密码绑定一次。
- 学生与微信账户：多对多。一个家长可以看多个孩子，一个孩子可以被父母两人看到。只有老师能建立这种绑定。
- 邀请：老师在小程序为班级生成一次性链接，7 天有效，同一个班可以并存多个。
- 家长通过邀请注册时只产生一条待处理申请，不直接建学生。同一账户重复提交会覆盖自己的待处理申请。
- 老师在小程序把申请关联到某个学生，此时才建立绑定，并把申请里的照片、中文名、家长手机号回填到学生档案的空字段，已有值不覆盖。
- 疑似重复的学生只提示，不自动合并。

## 出勤与作业

- 课堂提交里出勤只有「到」和「缺席」两种。「请假」只能课后在考勤页更正产生。
- 统计时凡不是「到」的都算未到堂。
- 「已补课」只影响考勤页统计，不改当日战报。
- 作业检查三态：没交（默认）、完成、需补。没有记录等于没交。

## 教材

教材有六种：新概念第一至四册（key 为 `'1'`–`'4'`）和青少版 A、B（`starterA`、`starterB`）。

| 教材 | 课数 |
|---|---|
| 新概念第一册 | 144 |
| 新概念第二册 | 96 |
| 新概念第三册 | 60 |
| 新概念第四册 | 48 |
| 青少版 A / B | 各 45（15 单元 × 3 课） |

青少版在课文复习下拉里显示为「Unit · Lesson」，存储仍是 1–45 的平铺序号。教材 key 一律是字符串；接口另外兼容旧页面发来的整数 1–4。

## 管理员

管理员是独立于「角色」的权限标记。角色（owner / teacher）只用于展示，不决定权限。

- 管理员只能通过服务器上的命令行授予或撤销，页面上没有任何提权途径。
- 高危操作集中在 `/admin`：删除班级、添加老师、修改成员密码。删除班级和改密码需要在同一次请求里复核管理员本人的密码。
- 普通老师在 `/teachers` 只能改显示名；登录名不可改。
- 页面添加的老师一律是普通老师，登录名全系统唯一。
- 删除班级是硬删除，连带清掉该班全部数据：学生、分组、上课记录、排班、收款、邀请与申请。机构奖章库、微信账户、已上传的照片文件不删。
- 改密码不会让已登录的会话失效，见 `kb/docs/deploy-and-ops.md`。

## 排班与收费

排班表（课程周期）是班级的计划层：老师在日历上点选上课日期和时间段，同一天可以排多节。收银台按「班级 + 课程周期」生成一个收款批次，批次下每个学生一张收款单。

### 应收怎么算

**全班一致，不看出勤**：应收 = 单价 × 课程次数 + 附加费（如书本费，按人头）。课程次数默认是排班节数，可以手动填写覆盖。

例：课程次数 18 节、单价 130 元、附加费 60 元，每名学生应收 18 × 130 + 60 = 2400 元，不论生成收款项时已经上了几节、该生到了几节。

- 为什么不按出勤：收款项经常在开课一段时间后才建，按到堂扣减会让之前缺过课的学生少收（2026-10 线上启航班出现 2400 / 2270 / 2140 / 2010 并存）。缺课不退费是常态，例外由老师逐个处理。
- 例外（中途入班、停课、优惠等）直接在编辑弹窗填「最终收款金额」，不按逐节出勤推算。
- 停课、归档学生只要建了收款单，应收也是标准值，需要时同样改最终金额。
- 「已上到堂」仍按出勤记录（到堂或事后补课算到堂，缺席、请假且未补不算），只用来提示老师哪些学生可能要调整。它是快照，生成或重置收款项时刷新。
- 周期起止是所选日期的最早和最晚一天，范围内该班所有实际上过的课都算「已上」，所以临时加课、调课自然覆盖。
- 课程次数手动填写后，未上节数 = 填写次数 − 周期内已上节数（最小为 0），只在批次抬头展示。填写的次数与排班节数相同时视为不覆盖，之后改排班仍然生效。

### 快照与重算

- 创建批次时逐学生算定节数与金额并存下来，之后不自动变化。
- 建单范围：全部在读学生，加上周期内到过堂的非在读学生。
- 生成批次后仍然可以修改排班，已有收款单不会跟着变，需要老师重算。
- 「重置收款项」（重新计算）只动未收款的收款单：刷新已上到堂，单价统一为批次单价，应收刷新为标准值；手动改过最终金额的保留其金额和备注；已确认收款的一律不动；快照之后新入班的学生补建收款单（同样按标准应收）。
- 重算时可以一并修改批次的单价、附加费和课程次数。
- 口径变更前生成的收款项，未收款且没改过金额的行重置一次即回到标准应收。
- 一个课程周期只能生成一个批次，防止重复收费。删除批次后可以重新生成；删除课程周期前必须先删它的批次。
- 删除批次会连带删除它的全部收款单，包括已收款的。删除学生同样会删掉该生的全部收款单，批次的人数和合计随之减少。

### 收款

- 确认收款只记确认时间和操作老师，不记渠道。可以撤销。收款本身发生在系统外，系统只做台账。
- 确认收款时间、快照时间、批次创建时间在库里存 UTC，页面按浏览器时区显示（`web/src/lib/utcTime.ts`）。
- 只有未收款的收款单可以编辑，已收款的要先撤销。可以改的是最终收款金额和备注；单价只在收款项层面设置。
- 编辑弹窗列出周期内逐节出勤（含排班外加课、未开课的排班日、未上的排班），只作参考，不决定应收。
- 最终金额与应收不同即标记为「手动改过」，改回相等则标记取消。
- 金额在存储和接口里一律是整数分，只有页面表单以元为单位。

### 计费日期用真实当天

seed 数据有一个固定的「参考今天」，只用于让演示数据的相对日期文案保持稳定。计费划分「已上」和「未上」必须用真实当天日期，否则生产账目会永远按那个固定日期切分。

「当天」固定按北京时间（UTC+8）计算（`server/src/util/time.ts` 的 `localToday()`），不看服务器进程时区。生产容器是 UTC，如果跟着进程时区走，北京时间 0–8 点会把昨天当成今天。

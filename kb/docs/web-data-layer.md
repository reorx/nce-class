# Web 数据层：读取、缓存与写后刷新

写给要改老师端 Web 页面、或给 Web 加新接口的开发者：页面数据从哪来、缓存多久、写操作后哪些页面跟着变、表单草稿和本地课堂为什么不会被后台刷新冲掉。

## 三层分工

- **API 层**（`web/src/api/`）：按业务领域拆分的请求函数和接口类型，只管收发与错误分类（HTTP 错误带状态码、断网是独立的网络错误、取消保持原生取消语义）。不重试、不弹提示、不跳登录。
- **Query 层**（`web/src/queries/`）：每个读取一个 `useXxxQuery`，每个写操作一个 `useXxxMutation`。缓存 key、新鲜度、写后刷新规则、身份切换都在这一层。
- **组件**：只用 Query 层的 hooks，类型从 API 层 `import type`。组件不拼 URL、不拼缓存 key、不自己保存一份服务器响应，写后也不手动 reload。

写后刷新规则集中在 `queries/cache-effects.ts`，按业务动作组织（「改学生姓名」「确认收款」「删除批次」……），由各领域 Mutation 在 hook 层调用。放在 hook 层而不是组件里，是为了组件提前卸载（比如保存后立刻跳页）时缓存维护照常完成。

## 缓存与新鲜度

| 数据 | 视为新鲜 | 无人使用后保留 |
|---|---|---|
| 普通业务数据（班级、课堂、考勤、收费、排班……） | 30 秒 | 30 分钟 |
| 老师列表、奖章库 | 5 分钟 | 30 分钟 |
| 当前登录身份 | 30 秒 | 30 分钟 |

- 新鲜期内回到页面直接用缓存，不发请求；过期后回到页面先显示缓存，后台刷新完再替换。过期只表示「允许刷新」，不是定时轮询。
- 窗口重新聚焦、网络重连时刷新已过期的数据，用来发现其他老师或小程序造成的变化。不承诺多端实时同步，缓存只在内存里，不持久化、不跨标签页同步。
- 读取失败只对网络错误和 5xx 重试一次；4xx 是确定结果，不重试。写操作从不自动重试。
- 同一份数据（同一个 key）在页面间、组件间共享：几个组件同时要老师列表只发一次请求。
- 收银台列表卡片在指针移入或获得焦点时预取完整批次详情，点进去不用等。

## 页面怎么展示读取状态

口径在 `web/src/lib/queryView.ts`，展示组件在 `web/src/components/QueryState.tsx`：

- **有数据就展示**，哪怕正在后台刷新或刚刷新失败。不能拿「正在请求」当整页白屏的条件。
- 没有数据、首次读取中：区域内显示加载。
- 没有数据、首次读取失败：404 显示「不存在或已被删除」，403 显示「没有权限」，其余显示原因和重试按钮。
- 查询没启用（条件未满足，比如弹窗没打开）不算加载中，不显示永久转圈。
- 已有内容的后台刷新失败：标题旁轻量提示「刷新失败，显示的是之前的内容 · 重试」，并弹一次错误 Toast。同一次失败无论几个组件在看都只弹一次；同样的文案 4 秒内不重复弹（断网时一批查询一起失败不刷屏）；取消请求不提示。

## 写操作之后

- 写接口返回的若是完整详情（班级详情、上课记录详情、批次详情、排班详情），直接写进对应详情缓存，不再重读；写入前先取消该详情在途的旧读取，免得旧响应晚到把新数据盖回去。
- 返回片段的（学生基本信息、单张收款单、提交课堂的结果）不冒充详情，相关缓存标记过期，正在显示的页面后台重读。收款汇总金额一律重读，不在前端推算。
- 真正删除的实体移除缓存，挂着的页面不会再去请求它；删除收款项时同时从收银台列表缓存里拿掉那一项，返回列表那一帧就看不到它。
- 写成功、随后的刷新失败：写操作仍报成功，刷新失败走后台错误提示，不会让老师以为没保存而重复提交。
- 收费口径不变：改排班、改考勤只刷新收费的展示，绝不自动触发重新计算，收款快照只在老师点「重置收款项」时变化。
- 考勤表即时反馈：进行中的修改叠加在服务端数据上显示；失败只回到这一格的服务端值，其他格（含并行进行中的）不受影响，整表重读也覆盖不了进行中的格。同一格保存中不能再改，撤销历史只收录服务端确认成功的修改。

## 表单草稿与后台刷新

编辑类表单在「开始编辑」那一刻从当前数据建立草稿，之后的后台刷新只更新底下的服务端数据，不覆盖输入：班级资源、作业模板（含上课记录页的模板弹窗）、作业布置与课堂信息、收费条款与费用编辑、排班编辑器、默认分组（改名输入中、保存进行中都以草稿为准，保存成功后回到服务端分组）。

需要「最新」数据才能建立草稿的场合，挂载时即便缓存新鲜也重读一次，读到后才初始化：课前配置的名单与分组、URL 直接开课的名单、编辑上课记录的原始记录与默认分组。排班编辑器只用新鲜的详情建立草稿。这样不会把几分钟前的旧名单固化进一节新课。

## 登录身份

- 身份只有一个来源：当前登录者的查询。结果为空表示未登录；没有结果且读取失败（断网、5xx、403）是读取失败，给重试，不当成退出。
- 登录、退出、已登录请求收到 401 时，先切换会话代次、取消在途请求、清空服务端缓存，旧账号晚到的响应写不进新账号的缓存。本地课堂草稿和提交备份从不清理。
- 会话过期（被动退出）跳登录页并记下来处，重新登录回到原页面；主动退出不记来处，下一个账号从首页开始。
- 读取失败的身份界面在任一写操作成功后会自动恢复：写成功证明会话有效，写操作结束前先重读身份。

## 课堂本地优先

课堂的业务规则见 `kb/docs/classroom-session-lifecycle.md`。数据层只补充三点：

- 本机已有某班进行中的课堂时，进入课堂页同步从本地恢复，不等任何服务器读取；身份还在读取或读取失败（断网刷新）也照常进课堂，只有确认未登录才去登录页。
- 后台刷新、React StrictMode 重挂载都不会重建本地课堂或生成新的幂等键：服务器数据到齐只定稿一次，定稿前再查一次本地存储，已有课堂一律优先。
- 结束课堂先冻结本次提交内容并写备份，再提交；失败后重试（包括刷新页面后重试）原样复用备份里那份内容，结束时间和幂等键都不变；老师失败后继续上课，课堂内容变了才重新冻结。

## 加一个新接口

1. API 层加请求函数和类型；读取函数接收取消信号并透传。
2. Query 层加 key（`queries/keys.ts`）、读取 hook 或写 hook。
3. 写操作在 `queries/cache-effects.ts` 加一条按业务动作命名的规则，写清回写哪里、哪些领域失效、删除时移除什么。
4. 先写行为测试：写后缓存矩阵用 `test-utils/cacheUniverse.ts`，页面级用 `test-utils/app.tsx` 渲染整个 App 驱动真实页面。
